# План доработок для деплоя в песочницу (MVP)

Дата: 2026-10-29  
Режим: sandbox-first, окно тестирования 1–2 недели.

## 1. Цель

Подготовить стабильный тестовый контур в песочнице, который:

- поднимается с нуля за 10 минут;
- проходит обязательный smoke-набор сценариев;
- содержит понятный пакет для тестера;
- не требует внешнего платного хостинга на этапе MVP.

---

## 2. Объём работ и приоритеты

## P0 — блокеры запуска и доступности

1. Подтвердить единый сценарий запуска в песочнице:
   - `npm install`
   - `npm run build`
   - `node dist/src/db/seed.js`
   - `node dist/src/server.js`
2. Проверить корректность окружения:
   - `PORT`
   - `DB_PATH`
   - `SESSION_SECRET`
   - `AI_MODEL`
   - `AI_API_KEY` (опционально)
   - `CLUB_TIMEZONE`
3. Проверить доступность ключевых URL:
   - `/`
   - `/offers`
   - `/trainers`
   - `/schedule`
   - `/health`

Результат P0: песочница стабильно поднимается и открывается для тестирования.

## P1 — надёжность тестового контура

1. Подготовить быстрый reset-процесс для песочницы:
   - пересборка;
   - повторный `seed`;
   - верификация демо-аккаунтов.
2. Проверить режимы AI:
   - `FAQ-only`;
   - `LLM+FAQ fallback` (при наличии валидного `AI_API_KEY`).
3. Подтвердить корректный fallback без ключа (без падений и 500 ошибок).
4. Уточнить и зафиксировать рабочие демо-учётки для тестера.

Результат P1: песочница восстанавливается после любого сбоя/перезапуска без ручной отладки.

## P1 — функциональная готовность к приёмке

Обязательный smoke-набор:

1. Публичный лид-магнит + авто-создание обращения.
2. Вход клиентом и админом.
3. Запись/проверка занятости/отмена.
4. Клиентский чат: `ai`, `trainer`, `human`.
5. Долгосрочная память: create/read/update/delete.
6. Админ-настройки AI и клуба.
7. Проверки изоляции ролей и CSRF.

Результат P1: все критичные сценарии воспроизводимо работают в песочнице.

## P2 — готовность к работе тестера

1. Подготовить «карточку тестера»:
   - URL песочницы;
   - логины/пароли;
   - список сценариев;
   - канал заведения дефектов.
2. Зафиксировать known issues/ограничения MVP.
3. Снять отчёт по прогонам (дата, commit, статус).

Результат P2: тестер может работать автономно без дополнительных пояснений.

---

## 3. План-график (оперативный)

## День 1

- Закрыть P0 полностью.
- Прогнать базовый smoke-набор.
- Зафиксировать рабочий commit для начала тестирования.

## День 2

- Закрыть P1 по надёжности и AI-режимам.
- Подготовить карточку тестера и known issues.
- Передать контур в тест.

## Неделя 1

- Обрабатывать баги приоритета High/Critical.
- Выпускать только точечные исправления без расширения scope.

## Неделя 2 (если нужна)

- Добить средние дефекты.
- Провести итоговый прогон приёмочного списка.
- Подготовить решение: закрыть песочницу или продлить окно.

---

## 4. Критерии готовности песочницы

Считаем песочницу готовой к тестированию, если одновременно выполнены условия:

1. Подъём стенда по инструкции ≤ 10 минут.
2. `/health` отвечает стабильно.
3. Все smoke-сценарии из раздела P1 проходят.
4. Есть пакет для тестера (URL, учётки, чек-лист, known issues).
5. Зафиксирован commit-идентификатор тестовой версии.

---

## 5. Управление изменениями в окно 1–2 недели

1. До freeze-даты допускаются только исправления, улучшающие прохождение сценариев.
2. После freeze-даты — только багфиксы High/Critical.
3. Новые функции, интеграции и продовые задачи — вне текущего окна.

---

## 6. Закрытие песочницы

По завершении тестового окна:

1. Снять финальный отчёт по качеству.
2. Зафиксировать перечень задач для прод-переноса (отдельный документ).
3. Остановить и закрыть песочницу.
4. Оставить GitHub как источник восстановления контекста.
