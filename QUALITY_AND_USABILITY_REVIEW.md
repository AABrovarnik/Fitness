# QUALITY AND USABILITY REVIEW

Дата проверки: 2026-10-19  
Формат: независимая оценка без изменения кода, данных и настроек рабочего контура.  
Базовый контур: `http://localhost:3010`  
Дополнительно: изолированные прогоны субагентов на `http://localhost:3020` и `http://localhost:3110`.

## 1) Выводы каждого агента

### Агент 1 — UX и сценарии посетителя/клиента/админа
- Подтверждён путь нового посетителя к заявке на пробную тренировку (`/` → `#lead`), заявка создаётся.
- Зафиксирован нестабильный сценарий клиентской записи в изолированном контуре (`3110`): после клика «Записаться» получено `Требуется вход`.
- Зафиксирована UX-проблема: при ошибке авторизации на клиентских страницах может отдаваться JSON-ошибка вместо человеко-понятного редиректа/экрана входа.
- Отмечена низкоприоритетная UX-шероховатость: формат времени с секундами перегружает интерфейс.

### Агент 2 — функциональные E2E-сценарии
- Подтверждены вход клиента и админа.
- Подтверждены запись/проверка занятости/отмена: первый клиент успешно записывается, второй получает отказ по capacity, отмена первой записи работает.
- Подтверждено редактирование профиля клиента (интересы).
- Зафиксировано отклонение по краткосрочной памяти в чате: система не ответила с использованием предыдущего сообщения.

### Агент 3 — мобильная версия и доступность
- Критичного «ломания» верстки на мобильном viewport не выявлено.
- Найдены проблемы доступности: отсутствующие label/aria-label в форме лид-магнита и в клиентском чате.
- Найдены UX/a11y-проблемы: часть touch-target ниже 44x44, нет явных focus-стилей.
- Отмечено отсутствие явного loading-state/защиты от повторной отправки для формы лид-магнита.

### Агент 4 — безопасность и изоляция данных
- Подтверждена корректная role-based изоляция (клиент не может выполнять админские действия; клиент не может менять/читать память и брони другого клиента).
- Подтверждено влияние обновлённой записи памяти/SQL на следующий ответ AI для того же клиента при сохранении изоляции между клиентами.
- Найден высокий риск: state-changing админские POST принимаются без CSRF-токена.
- Найден низкий риск: `GET /health` раскрывает служебные детали AI-конфига.

### Агент 5 — соответствие ТЗ
- Частичное соответствие ТЗ: базовые потоки реализованы, но часть функциональности из ТЗ не закрыта.
- Существенные расхождения: нет полноценных админских CRUD по ряду сущностей; не реализован полный цикл завершения посещения (`completed/no_show`) со списанием лимита при фактическом визите.
- Выявлены частичные расхождения по памяти (редактирование в UI, учет флага `memory_enabled`, аудит операций памяти).
- Есть несогласованность документации/дефолтной модели между `.env.example`, README и кодом.

## 3) Успешно пройденные сценарии

- Публичная заявка и путь к пробной тренировке: путь `/` → `#lead` рабочий, лид создаётся и отображается в админских обращениях.
- Вход клиента и администратора: подтверждён.
- Запись на занятие, проверка занятости, отмена: подтверждены в E2E-прогоне на `3010`.
- Просмотр и изменение своего профиля: подтверждено (интересы сохраняются).
- Просмотр абонемента: подтверждён в личном кабинете.
- Долгосрочная память: сохранение/просмотр/удаление подтверждены; изоляция между клиентами подтверждена.
- Попытки клиента читать/изменять данные другого клиента: отклоняются (`404`/`403` по проверенным кейсам).
- Попытки клиента выполнять административные действия: отклоняются (`403` по проверенным кейсам).
- Влияние обновлённой записи памяти/SQL на следующий ответ AI того же клиента: подтверждено в security-прогоне.
- Автотесты репозитория: `npm test` пройдено (`6 passed`).
