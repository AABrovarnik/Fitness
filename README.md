# FitClub Personal (MVP прототип)

> Обновлено: 19.10.2026. Независимый отчёт качества: `QUALITY_AND_USABILITY_REVIEW.md`.

Веб-прототип фитнес-клуба для 10–20 клиентов: публичная часть, кабинет клиента, админ-панель, чат с AI-консультантом/AI-тренером (безопасный демо-режим), SQL-память пользователя и разграничение доступа по ролям.

## Стек

- Backend/UI: Express + EJS + TypeScript
- База: SQLite (`node:sqlite`, файл `data/fitclub.db`)
- Авторизация: сессии + роли (`client`, `admin`)
- Тесты: Vitest + Supertest

## Что реализовано по ТЗ

- Публичная главная с тарифами, тренерами, расписанием и формой лид-магнита.
- Саморегистрация клиента и вход администратора.
- Личный кабинет клиента: обзор, профиль/предпочтения, записи, история нагрузок, чат, память AI.
- Запись на занятия с проверками:
  - активный абонемент,
  - вместимость,
  - пересечение с другими записями.
- Отмена записи клиентом только не позднее 2 часов до начала.
- Лимит абонемента не списывается при бронировании; списание предполагается при фактическом посещении.
- `no_show` не списывает лимит (MVP-правило).
- Лид-магнит автоматически создаёт чат-обращение.
- Админ-панель: сводка, клиенты, очередь обращений с ответом от администратора.
- Долгосрочная память `UserMemory` с изоляцией по владельцу и CRUD у клиента.
- Поддержка режимов `FAQ-only` / `LLM+FAQ fallback` в настройках админа.

## Актуальный статус качества (по независимому аудиту)

- Подтверждены рабочие сценарии: лид-магнит, вход клиента/админа, запись/проверка занятости/отмена, профиль, базовая изоляция ролей и данных.
- Открытые high-priority замечания: CSRF-защита state-changing форм, стабильность краткосрочной памяти AI, часть функциональных требований ТЗ по админскому CRUD и фиксации фактического посещения.
- Открытые medium замечания: a11y (labels/focus/touch-target), аудит операций памяти, ограничение служебной информации в `/health`.
- Детали, шаги воспроизведения и доказательства: `QUALITY_AND_USABILITY_REVIEW.md`.

## Быстрый запуск

1. Установить зависимости:

   ```bash
   npm install
   ```

2. Создать `.env` из примера:

   ```bash
   copy .env.example .env
   ```

3. Скомпилировать проект:

   ```bash
   npm run build
   ```

4. Заполнить БД демо-данными:

   ```bash
   node dist/src/db/seed.js
   ```

5. Запустить сервер:

   ```bash
   node dist/src/server.js
   ```

6. Открыть в браузере:

   - `http://localhost:3000`

## Ограничения текущего MVP

- Нет реальных интеграций оплат/CRM/турникетов.
- Для полноценного внешнего LLM-сценария требуется валидный `AI_API_KEY` и повторный интеграционный прогон.
- Нет push/SMS/email-рассылок.
- Нет мобильных нативных приложений.
